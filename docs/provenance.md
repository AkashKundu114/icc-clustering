# Experiment provenance

## Historical six-cohort protocol

An implementation describing the six-cohort protocol and writing partition files is available in [Git commit `49f3882`](https://github.com/AkashKundu114/icc-clustering/commit/49f3882fe5385913a9af1a5b89138c6ae6d95579). The relevant partition-writing scripts first appear in the tracked history in that commit. Local filesystem timestamps for the recovered partitions and per-fit records precede the commit timestamp, but those timestamps are not authenticated creation records and can be preserved or changed when files are copied. A search of ten local ZIP/TAR.GZ archives found no matching older producer implementation. These facts do not identify the actual historical producer. The code is therefore a documented protocol implementation, not verified provenance for the saved files.

The historical files have no contemporaneous execution manifest that binds their bytes to an exact code commit, cache hash, sample-identifier map, runtime environment, or invocation. The configured cohort caches do not preserve stable upstream sample IDs. Consequently, the available code documents a protocol, but does not establish that it generated the historical files. Historical execution provenance remains unverified.

## Later local run

A new full six-cohort run was executed locally on 2026-11-02 using the implementation available at commit `49f3882`. The input caches, partition assignments, fit records, and numerical outputs are not part of this public repository. Rights for the exact configured inputs and derived artifacts have not been cleared. The run therefore cannot be independently inspected or reproduced from a clean clone, and it does not retroactively authenticate the historical execution.

In that later run, three cross-method or cross-mode partition pairs previously flagged for exact equality were regenerated byte-for-byte with the recovered cache files; the cache SHA-256 values matched the values recorded for the later run. This demonstrates that those assignments can recur under the later implementation and those cache bytes, including one single-cluster output and two outputs with a singleton cluster. It makes degenerate or coarse algorithm output a plausible explanation. The historical producer and invocation remain unidentified, however, so this does not prove how the original files were created or establish that the duplicates are harmless. The necessary partition and cache evidence is not distributed here, so reviewers cannot independently check this local comparison.

## Thirteen-dataset score benchmark

Saved benchmark score rows were reaggregated locally and the rank calculation was independently checked. The original score-generating fit events, per-method implementation fidelity, and data-use permissions were not authenticated by that arithmetic check. Score inputs and numerical aggregates are not included in this repository pending rights review. This external-ARI comparison is distinct from the six-cohort stability analysis.

## What a provenance-complete release would require

A future authorized research-data release should bind each run to the exact source commit and configuration, dataset version and permitted input hashes, stable sample mapping where allowed, preprocessing fingerprint, random seeds, subsample indices, model outputs, failure records, environment, start/end times, and output checksums. Until those elements and the relevant redistribution rights are established, this repository makes no claim that historical model execution is authenticated or that the research-result package is publicly reproducible.
